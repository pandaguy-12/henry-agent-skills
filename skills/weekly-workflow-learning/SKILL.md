# Weekly Workflow Learning

## Purpose

Turn repeated corrections and successful methods into reusable improvements.

## Review sequence

1. Start from a bounded snapshot of changed workflows and failures.
2. Identify repeated corrections, recurring dead ends, and verified winning methods.
3. Ignore one-off progress logs and temporary environment failures.
4. Map each lesson to the existing skill that owns the work.
5. Prefer a small targeted patch over creating a narrow new skill.
6. Preserve stronger safety and verification rules.
7. Propose changes before applying them when the source is protected or shared.

## A valid learning signal

A lesson is durable when it changes how a class of work should be performed, explains why, and is supported by real execution or a user correction.

## Output

Keep the review short: current health, no more than three proposed improvements, evidence for each, and the smallest verification step.
